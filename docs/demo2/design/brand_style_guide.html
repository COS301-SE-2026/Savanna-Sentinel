Brand Foundation

From the colour of a danger alert to the wording of an explanation, they all come from the same decisions. Everything else in this guide follows from what's here.

Savanna Sentinel gives wildlife rangers access to poaching data. This includes incident reports, heatmaps, patrol coverage, community tip-offs and more. All of it readable on a phone in the field.

Values

The platform shows important data clearly and keeps everything else out of the way. A ranger in the field can't afford ambiguity. The app fails if important data doesn't hold contrast in direct sunlight.

Voice

The platform sounds like someone who's giving a simple report. Specific, not corporate. It doesn't overstate alerts or sweeten success. The same voice tells a patrol summary and a poaching incident without switching registers.

Tone

The urgency changes, the voice doesn't. A patrol summary reads like a summary. An alert gets to the point.

Using Tokens in Code

Every token here is a CSS custom property in frontend/src/styles/globals.css. Colour, spacing, and radius tokens live in Tailwind’s @theme block, so the token name is also the utility class. Motion tokens (duration, easing) stay plain CSS variables, referenced with arbitrary value syntax since Tailwind has no utility for those.

Guideline: prefer tokens over raw values

Raw hex values, pixel amounts, and millisecond literals should be avoided in component className strings when a token exists for the value. Colour, spacing, radius, shadow, and duration values should reference a token.

Wrong
className="bg-[#003A6B] p-4 rounded duration-150"
Correct
className="bg-brand-primary p-4 rounded-md duration-[--dur-fast]"
Token Class Category
--brand-primary bg-brand-primary Colour
--status-critical bg-status-critical Colour
--color-text-secondary text-color-text-secondary Colour
--sp-4 p-4 Spacing
--sp-6 gap-6 Spacing
--dur-fast duration-[--dur-fast] Motion
--ease-standard [transition-timing-function:var(--ease-standard)] Motion
Staying On-Brand with shadcn

shadcn's components (built on Radix UI) provide behaviour: focus trapping, keyboard navigation, ARIA wiring, positioning. They do not provide this project’s visual design. Each one ships with its own default Tailwind classes for colour (bg-primary, bg-background, and so on). Those get replaced with this guide’s own token classes when the component is built. The behavioural structure, DialogContent, SelectTrigger, PopoverContent, and so on, stays untouched.

shadcn's Button default variant ships as:

className="bg-primary text-primary-foreground hover:bg-primary/80"

It becomes:

className="bg-brand-primary text-color-text-inverse hover:bg-brand-primary/80"

Edit this in the component’s own file, not at each usage site. shadcn’s source is copied directly into frontend/src/components/ui/*.tsx, it is not an npm package, so editing it is expected and permanent, it will not be overwritten by anything except re-running the shadcn CLI for that specific component. Change the class string inside the component’s own variant definition (for Button, that is frontend/src/components/ui/button.tsx), and every existing and future usage of <Button variant="default"> picks it up automatically.

The same replacement applies to every component in the Component Map: keep the primitive for its behaviour, replace its default classes with the tokens and custom CSS documented for that component in this guide. No variable aliasing, no separate file to keep in sync, the token names are what get written in the component itself. If a new shadcn component is added later via the CLI, it arrives with default classes again, apply this same replacement to it once, using whichever spec section of this guide covers it (or the Component Map row if it has no dedicated spec).

Breakpoints

The app uses four breakpoints from Tailwind v4 defaults. Default styles are mobile, desktop styles are additive via md: or lg: prefixes. xl: and 2xl: are not used in this app. These are the target frontend's Tailwind breakpoints, not this static reference page's own layout, which uses its own max-width queries at 768px and 480px.

Prefix Min-width Typical context
(none) 0px Mobile portrait, single column
sm: 640px Mobile landscape, wider phones
md: 768px Tablet, two-column layouts unlock, map sidebar appears
lg: 1024px Desktop, full layout

Behaviour rules

  • The map sidebar (280px) appears at md: and above. Below md: it becomes a bottom drawer.
  • Data tables gain horizontal scroll at narrow viewports. Wrap them in an overflow-x-auto container.
  • The TopBar is the same height (56px) at all breakpoints.
  • Stat card grids: 1 column by default, 2 columns at sm:, 4 columns at md:.

Motion

Motion signals state changes. Duration and easing come from tokens, with one intentional exception: the skeleton loading shimmer runs on a hardcoded 1000ms interval that doesn't map to any duration token, since it's tuned to read as idle placeholder motion rather than a state transition. Wrap transform-driven motion that conveys entrance, exit, or spatial movement (panel slides, modal entrances, reveals) in @media (prefers-reduced-motion: no-preference). Simple non-transform state transitions (colour, background, border, and opacity swaps on hover/focus) are not gated. Neither are small transform micro-transitions on compact UI affordances (a dropdown chevron's rotation, a tooltip's few pixel offset). Their motion is too brief and too small to register as a vestibular trigger.

Hover each track below to see the animation.

Fast
150ms / var(--ease-standard)

Hover states, focus rings, icon swaps, tooltip enter.

Normal
250ms / var(--ease-exit)

Modal and panel exit animations.

Deliberate
400ms / var(--ease-enter)

Page reveals, modal entrance, drawer and analysis panel entrance.

Enter
cubic-bezier(0, 0, 0.2, 1) / decelerates

Elements arriving. Modals, drawers, notifications.

Exit
cubic-bezier(0.4, 0, 1, 1) / accelerates

Elements leaving. Dismissed drawers, closed modals.

Performance: will-change

Apply will-change: transform to elements whose animations will play frequently when interacted with. This tells the browser to promote the element to its own compositor layer before the animation starts, which reduces jitter.

Do not apply it globally. Each promoted layer consumes GPU memory, which matters on the hardware rangers carry. Add it only where a repeated animation is confirmed, and remove it from elements that stop animating.

Iconography

Icons use Lucide React (the lucide-react package), defaulting to a 2px stroke weight at 16-24px. Every icon has a text label or an aria-label. Colour shows status, but it's never the only indicator. Interior Suppression Rule

Low-risk cells that are fully surrounded by other Low-risk cells (or by the grid boundary) do not render their green fill. Only Low cells that share a border with a Medium, High, or Critical neighbour are shown, marking the edge of the safe zone. This prevents the safe zone from being painted solid green. All cells, including suppressed ones, remain clickable and open the popup.

Interior cell: 15% opacity

Boundary cell: 55% opacity

Condition Fill opacity Clickable

Low cell, at least one neighbour is Medium, High, or Critical 55% (default) Yes
Medium, High, or Critical cell 55% (default) Yes

The 8-neighbour check can't be expressed as a MapLibre paint expression on its own, since a feature can't inspect its neighbours' properties at render time. The API precomputes an is_interior boolean per cell and includes it in the GeoJSON. The paint expression (see the Risk Colour Scale section above) only branches on that flag.

Accessibility

The target is WCAG 2.2 Level AAA. Rangers use this app in the field, often with gloves in direct sunlight. Strong contrast is a requirement. Every interactive element has to work with a keyboard, and colour is never the only way to communicate status.

Principle Requirements in this design system
Perceivable
  • Body and primary text: 7:1 contrast minimum against its background (see table below). Secondary/muted text (--color-text-secondary) is held to large-text AA (3:1) rather than full AA (4.5:1) against --color-surface-bg, so per the colour decision table it is only used at --text-sm (14px) and up on surface-raised, and at 24px+ only on surface-bg, except on disabled/inactive controls, which are exempt from contrast requirements
  • Every image has descriptive alt text, decorative images use alt=""
  • Status shown by icon / label alongside colour, not colour alone
Operable
  • All functionality reachable by keyboard
  • Touch target: 44x44px
  • Focus order follows reading order, every interactive element shows a visible focus ring
Understandable
  • lang="en" on the html element, updated for any localised content
  • Form errors name the problem specifically ("Email is required", not "Invalid input")
  • Navigation is consistent across all pages
  • Labels are always visible, placeholder text does not replace labels
Robust
  • Correct ARIA roles and states on all custom components
  • Valid, semantic HTML

Voice and Tone

The voice doesn't change between a patrol summary and a critical alert. What changes is the urgency and the length. We never sugarcoat, we never overstate.

Write
  • 3 high severity incidents in Zone A-3.
  • Report synced successfully.
  • No tip-offs in the last 48 hours.
  • GPS signal lost. Check device.
  • Submit this report? It will be logged and synced to the server.
Never write
  • Oops! Something went wrong on our end.
  • Your report was submitted!
  • It looks like there are no tip-offs yet.
  • We were unable to establish a GPS connection at this time.
  • Are you sure you want to do this? This action cannot be undone!
Critical alerts: action first
  • Active poaching reported in Zone 4. Last updated 10:31 SAST.
  • Signal strength critical.
  • Sync failed. Tap to retry.
Never: passive, hedged, or dramatic
  • There is some potential poaching activity detected.
  • We're experiencing some difficulties syncing your data right now.
  • Immediate action may be required!
