00 · Who We Are

About Savanna Sentinel

Understanding who we are and what we stand for shapes every design decision, from the words on a button to the colour of an alert.

Purpose

Savanna Sentinel exists to give wildlife rangers the intelligence they need to protect vulnerable species in real time, in the field, without friction. Every feature we build has to earn its place against that purpose.

Values

Precision over noise. Speed saves lives. Every sighting counts. Data must never outrun the ranger who acts on it. We believe accessibility is not a nice to have, it is part of the product.

Voice

Calm, direct, expert. Never alarmist, never bureaucratic. Our voice is the same in a dashboard label, a notification, and a critical incident alert, because rangers need to trust us in all three situations.

Tone

A patrol summary is measured and factual. A critical poaching alert is urgent but not panicked. An empty state message is reassuring. Same voice, different room. We adjust tone to the moment without losing character.

01 · Colours

Colour Palette

Tones chosen for readability on map heavy interfaces. All colours are defined as CSS custom properties in the Tailwind config.

Why this palette? Rangers work in high stress, fast moving environments often outdoors, on screens with variable lighting. The palette is built around deep navy blues because they read as authoritative and calm without the aggression of pure black, and they provide strong contrast for map overlays and text. Steel blue and the secondary tones give us enough range to structure complex dashboards without reaching for unrelated hues. Spot colours are strictly reserved for status communication, green means safe, orange means caution, red means danger, so the meaning is never ambiguous.

02 · Typography

Typography

Inter is the primary typeface, loaded via Google Fonts. It matches shadcn/ui's default type config out of the box.

Why Inter? A typeface speaks before a single word is read. Inter is a humanist sans-serif designed specifically for screen readability, it performs equally well at the large sizes of a dashboard heading and the small sizes of a coordinate label. It carries a sense of calm competence rather than corporate stiffness or creative flair, which aligns with our voice. We use only four weights (400, 500, 600, 700) because more weights introduce visual noise without adding hierarchy. Line-heights are always paired with size tokens because size without line-height is a half-decision.

03 · Logo & Iconography

Logo & Iconography

Keep a clear exclusion zone around the logo of at least 50% of its height. Use Lucide React for all icons at a consistent 2px stroke weight.

Why these icon choices? Each icon type on the map has a distinct shape and a distinct spot colour, so it remains recognisable even at small sizes or for users with colour vision deficiency, colour alone never carries the full meaning. Lucide React is used throughout because its consistent 2px geometric stroke style aligns with the clean, technical character of our UI and avoids the stylistic inconsistency that comes from mixing icon libraries.

04 · Principles

Design Principles

These four principles guide decisions across the desktop dashboard and mobile PWA. Every component, layout, and interaction should be traceable back to at least one of them.

Consistency

shadcn components and Tailwind utilities are used throughout. When design and code share the same language, the product feels like it was built by one team with one intention, because it was.

Simplicity

The map is the primary focus. UI chrome exists to support the map, not compete with it. When in doubt, remove rather than add, a ranger in the field cannot afford cognitive overhead.

Responsiveness

Tailwind's responsive prefixes (sm: md: lg:) handle layout at every screen size. The same content must work on a wide desktop monitor and a mobile PWA without redesigning for each.

Accessibility

WCAG 2.1 AA is the floor, not the ceiling. Accessibility is built into every token, every component, and every guideline, it cannot be added at the end of a sprint.

05 · Components

UI Component Styling

All components build on shadcn/ui with defaults overridden per component file. Do not revert to shadcn defaults.

Why shadcn/ui? shadcn gives us unstyled, accessible primitives built on Radix UI, which handles ARIA roles, keyboard navigation, and focus management correctly by default. We override the visual layer to match our design tokens while keeping the accessible behaviour intact. The result is components that look like Savanna Sentinel and behave correctly for every user, including those relying on keyboard navigation or screen readers.

Buttons

Primary uses a solid Dark Blue fill with white text. Secondary is outlined. Both use a 6px border radius and a visible focus ring for keyboard users.

06 · Accessibility

Accessibility

All interfaces must meet WCAG 2.1 AA. Radix UI primitives (via shadcn) handle ARIA roles correctly by default. Do not disable this.

Why we take this seriously. Accessibility is a system property, it cannot be bolted on at the end of a sprint. It has to be baked into every token, every component, and every guideline. Rangers may use the platform in conditions that make interaction difficult: bright sunlight, gloves, or stress. Accessible design often makes the product better for everyone in those conditions, not just users with disabilities.

Colour Contrast

All text and background combinations need at least a 4.5:1 contrast ratio for normal text, and 3:1 for large text. Never rely on colour alone to convey state, always pair with an icon or label.

White on Dark Blue - Passes AA (≈10.7:1)
Dark Blue on Off-White - Passes AA
White on Dark Grey - Passes AA (≈14.7:1)

Keyboard Navigability

Every interactive element, forms, map toggles, time sliders, must be reachable and operable by keyboard. All focusable elements need a visible focus-visible:ring style. No keyboard traps.

Screen Reader Compatibility

Radix UI primitives handle ARIA roles by default. Custom components must also include:

  • Proper ARIA labels on icon-only buttons
  • Semantic HTML: <nav>, <main>, <article>
  • Live regions for toast notifications
  • Alt text on all map markers and images
